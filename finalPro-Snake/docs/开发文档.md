## 1. 项目功能介绍

### 1.1 核心玩法
- 经典贪吃蛇：蛇持续移动，吃到食物得分并变长。
- 撞墙或撞到自身则游戏结束。

### 1.2 交互功能
- 键盘：`W/A/S/D` 控制方向。
- 暂停：`Esc` 暂停/继续。
- 退出：`Ctrl + C` 或点击菜单 Quit。
- 鼠标：在右侧菜单面板点击按钮进行操作（开始新游戏、选择难度、返回、退出等）。

### 1.3 计分与难度
- 分数随吃到食物累加（每次固定加分）。
- 难度影响初始速度；得分越高，移动越快。

## 3. 项目总体设计（模块划分与调用关系）

项目采用“文件=模块”的方式拆分功能，入口在 `main.asm`：

- `main.asm`
  - `start -> Init -> MainController -> Quit`
  - 通过 `%include` 引入其他模块。

- `Game.asm`：游戏流程控制
  - `Init`：屏幕初始化、菜单绘制、地图绘制、鼠标初始化
  - `GameStart`：开始新游戏（清屏、重画地图、初始化蛇、初始化计时器/随机种子/食物、重置状态）
  - `MainController`：主循环（键盘/鼠标监听 + 暂停/结束判断 + 计时器节拍驱动移动）

- `Drawer.asm`：绘制/屏幕管理
  - 保存/还原原屏幕内容
  - 隐藏/恢复光标
  - 画线（矩形边框）、画方块（蛇身/擦除）

- `Snake.asm`：蛇的核心逻辑
  - 蛇的“分段队列”数据结构
  - 转向、移动、擦尾、增长、碰撞检测
  - 速度控制（用“进度条”思想控制调用 Move 的频率）

- `Food.asm`：食物与随机数
  - LCG（线性同余）随机数
  - 在空白位置放置食物
  - 检测是否吃到食物、更新分数

- `Keyboard.asm`：键盘输入
  - int 21h 读取键盘缓冲
  - 将按键映射为方向/控制操作

- `Mouse.asm`：鼠标输入
  - int 33h 设置鼠标与监听按键抬起
  - 将像素坐标转为字符坐标并命中按钮区域

- `Menu.asm`：菜单与分数显示
  - 右侧面板背景与边框

## 4. 技术细节

### 4.1 实模式与 COM 程序模型
- **实模式（Real Mode）**：地址由“段:偏移”组成，物理地址计算为：

$$\text{Physical} = \text{Segment} \times 16 + \text{Offset}$$

- **COM 程序特点**：
  - `org 100h`：指令/数据从偏移 0x100 开始。
  - 通常 `CS=DS=ES=SS` 指向同一段（由 DOS 装载器设置），因此本项目可以直接用 `[变量]` 访问数据区。

### 4.2 文本模式显存与颜色属性
- 80×25 彩色文本模式显存位于：`0xB800:0000`。
- 每个屏幕字符占 2 字节：
  - 第 1 字节：ASCII 字符码
  - 第 2 字节：属性（颜色）

颜色属性位分布（常见约定）：
- 低 4 位：前景色（0～15）
- 高 3 位：背景色（0～7）
- 最高位：闪烁（blink）

屏幕坐标 (row, col) 映射到显存偏移：

项目中 `Drawer.asm` 的 `GetDisplayLocation/GetLocValue` 正是围绕这个公式实现。

```asm
GetDisplayLocation:
  push bp
  mov bp,sp

  push ax
  push cx

  mov ax, VIDEO_ADDRESS
  mov es, ax
    
  mov ax,word [bp+6]        ; y
  mov cl, SCREEN_WIDTH*2    ; 一行字节数 = 80*2
  mul cl                    ; AX = y * 160
  add ax,word [bp+4]        ; + x
  add ax,word [bp+4]        ; + x（等价于 + 2x）
  mov di, ax                ; DI = (y*80 + x) * 2

  pop cx
  pop ax

  mov sp,bp
  pop bp
  ret
```

逐行解释：
- 栈传参：调用者 `push x`、`push y` 后 `call`，在被调者中 `[bp+4]` 取到 `x`，`[bp+6]` 取到 `y`。
- `mul`：无符号乘法。这里的目的就是得到 `y*160`（一行 80 字符 * 每字符 2 字节）。
- `add ax, x` 两次：实现乘 2（字符占 2 字节），避免额外 `shl`。
- 最终得到 `DI`，后续可以直接写 `word [es:di]`。

### 4.3 函数调用约定（栈帧与参数）
项目大量过程使用如下模式：
- 进入过程：
  - `push bp`
  - `mov bp, sp`
- 参数从栈上读取：`[bp+4]、[bp+6]...`
- 返回前：
  - `mov sp, bp`
  - `pop bp`

并遵守约定：
- 被调用者负责保存通用寄存器现场（常见：`push ax/bx/cx/dx/si/di`），返回前 `pop` 还原。
- 有返回值时统一放在 `AX`。

这对应课程里“过程调用/栈传参/栈帧”的核心内容。

### 4.4 DOS 中断的使用

#### 4.4.1 获取系统时间：int 21h / AH=2Ch
- `Timer.asm` 使用 `int 21h, AH=2Ch` 获取系统时间。
- 关键字段：`DL` 通常表示 1/100 秒（0～99）。
- 本项目用轮询方式实现“节拍”，例如 30ms（0.03s）触发一次。
- 处理跨秒：如果当前 `DL < last_time`，则把当前值视为 `DL+100` 再做差。

#### 4.4.1.1 代码：计时器节拍检测（`TimerCheck`）

代码节选自 `Timer.asm`，返回 `AL=1` 表示应该刷新/移动一次：

```asm
UNIT_TIME equ 3

TimerCheck:
  push dx
  push cx
  mov ah,2ch
  int 21h            ; 取系统时间，DL=1/100 秒（0..99）
  pop cx
  mov dh,dl          ; 备份当前 DL 以便成功时写回 last_time

  cmp dl, [last_time]
  jns TimerCheck.next
  add dl, 100        ; 处理跨秒：例如 2 < 98，视作 102
TimerCheck.next:
  sub dl, [last_time]
  cmp dl, UNIT_TIME
  jns TimerCheck.check_success

TimerCheck.check_failed:
  pop dx
  mov al,0
  ret

TimerCheck.check_success:
  mov al,1
  mov [last_time], dh
  pop dx
  ret
```

要点：
- DOS 的 2Ch 号功能给出的是“时间片”而不是中断回调；所以这里用轮询（死循环）实现“软件定时”。
- `DL` 只有 0..99，会回绕；因此用“`DL+100`”解决跨秒差值计算。

#### 4.4.2 键盘缓冲读取：int 21h
- `Keyboard.asm` 先用 `AH=0Bh` 检查键盘缓冲是否有键。
- 若有，再用 `AH=08h` 读取字符（不回显）。

#### 4.4.3 退出程序：int 21h / AH=4Ch
- `Drawer.asm` 的 `Quit` 最终调用 `int 21h` 结束进程。

### 4.5 鼠标中断：int 33h
- `Mouse.asm` 通过 `int 33h` 初始化鼠标、设置可移动区域、显示/隐藏指针。
- 监听事件使用 `AX=06h`（按键抬起/事件查询类功能）。

**坐标转换关键点**：
- 鼠标返回的是像素坐标（CX、DX）。
- 文本模式一个字符格约为 8×8 像素。
- 因此将像素坐标除以 8 得到字符坐标，然后再转为显存偏移：

$$\text{offset} = (row \times 80 + col) \times 2$$

之后通过比较 offset 是否落在某个按钮占用的 [start, end) 区间，决定触发哪个功能。

#### 4.5.1 代码：鼠标像素坐标 → 文本坐标 → 显存偏移

代码节选自 `Mouse.asm` 的 `MouseListen`，展示了“除以 8 对齐到字符格 + 转 offset”的全过程：

```asm
mov ax,06h
mov bx,0
int 33h
cmp bx,0
jz MouseListen.finish      ; BX=0 表示没有事件

; DX 是像素 y，先 /8 得到字符行号
push cx
mov ax,dx
mov dx,0
mov cx,8
div cx
mov dx,ax                  ; DX = row

; CX 是像素 x，/8 得到字符列号
pop cx
push dx
mov ax,cx
mov dx,0
mov cx,8
div cx
mov cx,ax                  ; CX = col

; offset = (row*80 + col) * 2
pop dx
push cx
mov ax,dx
mov cx,80
mul cx
pop cx
add ax,cx
mov cx,2
mul cx                     ; AX = offset
```

为什么“/8”：因为鼠标驱动给的是像素坐标，而文本模式每个字符格通常是 8×8 像素（DOSBox 下也近似如此）。

## 5. 关键算法与数据结构设计

### 5.1 蛇的分段队列结构

#### 5.1.1 为什么要“分段”
蛇在每一帧都移动，但实际变化只发生在：
- **头部前进 1 格**
- **尾部后退 1 格**

如果把蛇当成“每一格都存下来”的点集，每次移动都要整体平移或搬运数据，成本高且代码复杂。

本项目采用“线段队列”的思路：
- 把蛇拆成若干连续线段，每个线段一个节点。
- 每次移动只更新头节点和尾节点。

#### 5.1.2 节点布局
在 `Snake.asm` 中，节点结构为：
- `loc dw`：该线段“起点”或关键位置的显存偏移
- `dir db`：方向（项目内部编码）
- `len db`：该线段长度

节点大小固定为 4 字节（`SNAKE_NODE_SIZE = 4`）。

#### 5.1.3 队列存储方式：环形缓冲
- 使用 `mem: times MEM_SIZE db 0` 作为内存池。
- `queue_start/queue_end` 是“字节偏移指针”，通过对 `MEM_SIZE` 取模实现循环。

这对应数据结构课/汇编课里“用数组模拟队列”的思想。

#### 5.1.4 代码：环形队列申请/释放节点（`CreateSnakePtr/DeleteSnakePtr`）

这里节选 `Snake.asm` 的节点管理代码，重点看“用除法取余实现循环指针”。

```asm
SNAKE_NODE_SIZE equ 4
MEM_SIZE equ 7500

CreateSnakePtr:
  mov bx,word [queue_end]
  add bx, mem            ; BX = mem + queue_end（新节点地址）

  mov dx,0
  mov ax, SNAKE_NODE_SIZE
  add ax, word [queue_end]
  mov cx, MEM_SIZE
  div cx                 ; DX = (queue_end + 4) mod MEM_SIZE

  mov word [queue_end],dx
  mov ax,bx              ; 返回 AX=新节点地址
  ret

DeleteSnakePtr:
  mov dx,0
  mov ax,SNAKE_NODE_SIZE
  add ax, word [queue_start]
  mov cx,MEM_SIZE
  div cx                 ; DX = (queue_start + 4) mod MEM_SIZE
  mov word [queue_start],dx
  ret
```

解释：
- 16 位实模式下没有“自动取模指令”，常用技巧是 `div` 后取余数 `DX`。
- 把 `queue_start/queue_end` 都维护成 0..MEM_SIZE-1 的偏移，形成环形队列。
- `CreateSnakePtr` 返回的是 **指针（地址）**：`AX = mem + queue_end_old`。

### 5.2 转向判定（取余思想落地）

项目将方向按顺时针编码为 1..4（左、上、右、下），可用取余实现左转/右转：

- 左转：

$$dir = (dir-1-1)\bmod 4 + 1$$

- 右转：

$$dir = (dir-1+1)\bmod 4 + 1$$

当玩家输入方向键时（存入 `now_dir`），`CalDirection/CheckDirection` 会判断是否是合法转向（避免 180° 掉头），若需要转向则在头部前插入一个新节点（`len=0`），让后续移动自然形成“拐点”。

### 5.3 碰撞检测
- `CheckWall` 读取头部位置的显存内容：
  - 若为墙体字符（墙颜色）或蛇身字符（蛇颜色），则 GameOver。

#### 5.3.1 代码：把“屏幕字符”当作碰撞判定依据（`CheckWall`）

节选自 `Snake.asm`：

```asm
CheckWall:
    mov bx,word [header_str]
    mov di,word [bx]       ; DI = 头部的显存偏移

    mov ax,VIDEO_ADDRESS
    mov es,ax
    mov ax,word [es:di]    ; 读取屏幕上当前格子的字符+颜色

    cmp ax,WALL_COLOR
    jz CheckWall.hit_wall
    cmp ax,SNAKE_COLOR
    jz CheckWall.hit_wall
    mov ax,0
    ret

CheckWall.hit_wall:
    call GameOver
    mov ax,1
    ret
```

这段代码体现了一个非常“工程化”的取舍：
- 不维护地图数组，直接用“显存里的字符”作为世界状态。
- 前提是：墙/蛇身/空白对应的显存值要稳定一致，否则判定会错。

这种做法非常“汇编友好”：
- 不需要额外维护一张地图数组
- 直接以“屏幕上的字符”作为碰撞判定依据

### 5.4 增长逻辑
- `Food.asm` 维护 `food_num`（吃到的食物计数）。
- `Snake.asm` 的 `Enlongate`：当 `food_num >= ENLONGATE_NUM` 时，让蛇在当前节拍额外前进一次但不擦尾，相当于“增长一格”，然后清零计数。

### 5.5 速度控制（进度条模型）

`RealMove` 使用“进度累积”控制移动频率：
- 每个节拍：

$$rate += init\_v + \lfloor score/50 \rfloor$$

- 当 `rate >= MAX_RATE`：
  - `rate = 0`
  - 调用一次 `Move`

#### 5.5.1 代码：速度累积与触发移动（`RealMove`）

节选自 `Snake.asm`：

```asm
RealMove:
    mov dx,0
    mov ax,word [score]
    mov cx,50
    div cx                 ; AX = score/50（商），DX=余数

    add ax,word [rate]
    add ax,word [init_v]   ; init_v 由难度决定
    mov word [rate],ax

    cmp ax, MAX_RATE
    jb RealMove.finish

    mov word[rate],0
    call Move

RealMove.finish:
    ret
```

解释：
- `div cx`：16 位无符号除法，被除数是 `DX:AX`；因此先 `mov dx,0`。
- 速度随分数增长：`score/50` 相当于每 50 分提高一个档位。
- 与其调 Timer 单位，不如用累积进度控制 Move 的触发频率，逻辑更清晰。

优点：
- 不需要动态调整 Timer 的单位时间
- 难度与加速都可以通过修改累积增量实现

## 6. 界面设计与绘制实现

### 6.1 为什么直接写显存
在 DOS 环境下，直接写 B800 文本显存有这些优势：
- 速度快、控制力强
- 不依赖高层库
- 适合“每帧重绘/局部重绘”

### 6.2 保存/还原屏幕现场
- `ScreenInit` 会把原屏幕 2000 个字符对复制到 `old_screen`。
- `Quit` 时把 `old_screen` 写回显存，避免程序退出后破坏用户原有屏幕。

### 6.3 光标隐藏
- 通过对 0x3D4/0x3D5 端口读写设置光标位置，使其不可见。
- 退出时恢复原光标。

### 6.4 菜单面板与按钮
- 菜单通过 `Menu.asm` 的 `PrintStrColor` 向显存写入字符串。
- 为避免鼠标驱动影响绘制，绘制时会 `HideMouse`，绘制后再 `ShowMouse`。

#### 6.4.1 代码：字符串写显存（`PrintStrColor`）

节选自 `Menu.asm`，展示了“把字符写入 AL、颜色属性在 AH”的常见写法：

```asm
; void PrintStrColor(u8* str,u16 loc,u16 color)
PrintStrColor:
  mov ax,VIDEO_ADDRESS
  mov es,ax
  mov di,word [bp+6]     ; 起始显存偏移
  mov bx, word [bp+8]    ; 字符串指针
  mov ax, [bp+4]         ; AX = color + char（循环内改 AL）

PrintStr.loop:
  mov al, byte [bx]      ; AL=当前字符
  cmp al,0
  jz  PrintStr.finish
  mov word [es:di],ax    ; 写入 (字符+颜色)
  add di,2
  inc bx
  jmp PrintStr.loop

PrintStr.finish:
  ret
```

理解要点：
- 文本模式下每格 2 字节，写入 `word [es:di]` 一次就能同时写字符和颜色。
- 把颜色常量放在 `AH`（属性字节），循环内只改 `AL`（字符字节），能减少寄存器与内存操作。

## 7. 项目开发流程

### 7.1 第 1 阶段：跑通最小可执行程序
- 目标：能在 DOSBox 中运行并退出。
- 步骤：
  1. `org 100h` + 一个 `start` 标签
  2. `int 21h, AH=4Ch` 正常退出
  3. 用 NASM 编译为 COM 并在 DOSBox 执行

### 7.2 第 2 阶段：屏幕绘制基础设施
- 目标：能清屏、画点/画线、计算 offset。
- 关键点：
  - 统一封装 `GetDisplayLocation`，不要在各处手写 offset 计算
  - 封装 `DrawLine/DrawSquare`，提升复用

### 7.3 第 3 阶段：地图绘制
- 目标：画出固定矩形边框。
- 关键点：
  - 竖边宽度与横边宽度差异（字符宽高比）

### 7.4 第 4 阶段：输入系统
- 键盘：先能读到 W/A/S/D
- 鼠标：先显示鼠标，再做按钮命中

### 7.5 第 5 阶段：蛇的最小移动
- 先不做食物、不做增长
- 每次 tick：
  - 擦尾 + 画头
  - 碰墙结束

### 7.6 第 6 阶段：食物与得分
- LCG 随机
- 空位校验
- 计分显示（十进制转换）

### 7.7 第 7 阶段：难度、暂停、菜单完善
- `is_pause/is_end` 状态机
- 按钮显示/隐藏
- 速度曲线调参

## 8. 调试与验证方法

### 8.1 分层验证
- 先验证“绘制函数正确”：画线/画方块/填充区域
- 再验证“输入正确”：按键能更新变量、鼠标点击能触发函数
- 最后验证“逻辑正确”：移动/碰撞/食物/得分

### 8.2 常用排错技巧
- 在屏幕某固定位置输出关键变量（例如 `now_dir/score/is_pause`），相当于“屏幕日志”。
- 对关键过程入口/出口临时写入特定字符，确认流程是否执行。
- 遇到“偶发 bug”，把循环节拍放慢（调大 UNIT_TIME 或减小 rate 增量）。

### 8.3 典型 Bug 场景
- **黑色条块/背景未覆盖**：通常是“擦除时写了 BLANK（灰底）而不是面板底色”。
- **转向异常**：检查方向编码是否一致、是否允许 180° 掉头。
- **食物刷到墙/蛇身**：空位检测要基于显存内容。

写汇编最怕“到处散落的魔数与重复逻辑”。通过写这个项目让我意识到：
- 把 **坐标→显存偏移**、**画线**、**画方块** 抽成过程，后面开发速度会明显提升。
- 把“主循环驱动”与“移动一次的逻辑”分开（`TimerCheck/RealMove/Move`），能让节拍、难度、加速策略都更容易调。

### 9.2 用屏幕当作“数据结构”是很实用的技巧
碰撞检测直接读显存：
- 简化了地图维护，不需要额外数组
- 但也要求“绘制层与逻辑层一致”，否则会出现判定错误

这是一种典型的“空间换结构/用现有状态当真相源”的工程取舍。

### 9.3 过程调用与寄存器约定让大型汇编可维护
当文件多、过程多时：
- 若不统一寄存器保存约定，调用者很难安心复用函数
- 用栈传参 + 栈帧让每个过程像“有签名的函数”，也更接近课程中结构化程序设计

### 9.4 调参与体验：技术选择影响游戏手感
例如增长逻辑选择在 `Enlongate` 处额外前进一格，而不是“吃到就立刻增长”，会影响：
- 玩家在吃到食物后是否有反应时间
- 是否出现因为瞬间增长导致撞墙的挫败感

这种体验差异来自很小的技术实现点，值得在开发时刻意记录。
